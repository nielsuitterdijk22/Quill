- 2026-11-12 — PR B4 (serverless epic): engine-backed code browse shipped, flag-off. The browse APIs (ListBranches, ListCommits, GetCommit+diff, GetContents with per-entry last commits, RenderMarkdown) now serve **own-engine repos from the hydrated bare repo by shelling out to upstream git**, byte-compatible with the Forgejo DTO shapes (frontend unchanged). Two deliberate deviations from the roadmap's "extract the gitea git module" line, recorded because the roadmap text says so: (1) **shell-out instead of the gitea module for reads** — the module is itself a wrapper that shells the same git binary (CommitsCount/LogWriter/ls-tree are exec under the hood), so B4 buys identical behavior with zero new dependencies, consistent with the B2/B3 DNA ("upstream git does the actual work"); the module's real value is B5's merge/diff machinery, where it will be evaluated with concrete merge-problem evidence, not for thin read wrappers. (2) **goldmark for markdown on engine repos** (first new engine-era dependency, chosen precisely because it IS gitea's markdown core): GFM extension + linkify, and crucially NO WithUnsafe — raw HTML is escaped by goldmark's default, so the render is sanitized by construction. Forgejo repos keep the client's RenderMarkup until Phase D. Routing design: a repo with a `git_repo_state` referee row serves from the engine; a repo without one routes to Forgejo (which fails closed ErrUnavailable while Forgejo is disabled) — the discriminator is the SAME referee row pushes commit through, so a migrated repo flips browse behavior atomically with its git truth. The public-read bypass and anonymous-404 semantics moved verbatim into the new resolveBrowseRepo (metadata calls like GetRepo never touch a git backend, preserving prior availability semantics). Commit-record parsing uses %x1f/%x1e separators (record terminator needed because %B bodies contain newlines; for-each-ref does NOT expand %xNN escapes — separator bytes go in literally). Verified end to end: the integration tests push a real repo through the mounted smart-HTTP stack (B3 machinery: lease, referee CAS, finalize) and then exercise every browse op — branches/commits/path-filter/diff/root+file contents/base64/tag refs/last-commits/NotFound semantics — plus anonymous public reads, empty-repo ErrEmptyRepo, and the inverted-discriminator proof (a repo whose referee row is stripped routes to the disabled Forgejo backend).

- 2026-11-12 — PR B3 (serverless epic): git engine write path shipped, flag-off. Pushes serve `git-receive-pack` v0 over the same `/git` mount. **The load-bearing design change vs the roadmap sketch: NO git hooks.** Forgejo needs receive-pack hooks because its git serving runs a process away from its policy layer; our integration point is the HTTP handler itself — stateless-rpc delivers the client's command list (old/new/ref pkt-lines) before the pack bytes, so policy runs in-handler with plain Go errors, receive-pack runs with buffered stdout, and finalize (packs→bucket, referee CAS, manifest) completes BEFORE the client sees success; a rejected push never touches the bucket. Three more decisions recorded as deliberate: (1) **Single-writer serialization is a `push_leases` Postgres row, not the sketched advisory lock** — advisory locks are session-bound and a push spans processes (handler → receive-pack), while a lease row (`repo_id` PK, holder, expires; TTL 10 min) works cross-instance (Serverless scales out) and self-heals crashed writers without a sweeper; the roadmap's "advisory lock" idea fails outright in the cross-process shape. (2) **`receive.unpackLimit=1` on every receive** — receive-pack's default explodes pushes under 100 objects into loose objects, which would silently never reach the bucket ("bucket is the repository"); forcing pack-retention is a correctness requirement, not an optimization (plus `gc.auto=0`: no background gc on a disposable cache). (3) **Commit order is referee-first, manifest second** (Postgres is the truth; the manifest a repairable view), with a bounded manifest retry ending in a lease-justified unconditional write — only the lease holder may write manifests, so it cannot clobber anyone. Policy scope decision: a pre-receive hook can only see ref old/new — so pre-receive enforces `BlockForcePush` (force pushes via `git merge-base --is-ancestor` + deletes) exactly, while RequiredApprovals/RequirePullRequest/RequireStatusChecks are merge-gate (B5) concerns and are NOT enforced at push time. UX decision: guard rejections are a synthesized v0 report-status (sideband-aware), so git renders its native "! [remote rejected] main -> main (reason)" — the same shape a hook decline produces; plain HTTP 403s hide the reason behind "the requested URL returned error". Interim states documented in code: actor is "anonymous" until B6's token auth (seam: `ReceiveConfig.Actor`); pushes capped at 256 MiB (413); lease-held → 423, referee-divergence → 409 fetch-first. Verified with REAL `git push` round trips (two sequential pushes; manifest asserts refs/packs/push_history/storage_bytes; referee revisions advance exactly; clone-equals-original) plus guard/lease/divergence rejection tests proving bucket+referee stay untouched, gated store lease tests (acquire/release/expiry steal/same-holder re-acquire), and gated platform guard tests (fold all three policy scopes through `EffectiveBranch`). Still inert in production: the whole `/git` mount exists only under `QUILL_GIT_ENGINE_MODE=own`, and B6 authenticates before any cutover.

- 2026-11-12 — PR B2 (serverless epic): git read path shipped, flag-off. Smart HTTP v0+v2 served by shelling out to `git upload-pack --stateless-rpc` (protocol v2 via `GIT_PROTOCOL` env passthrough — upstream git does all protocol handling; the engine only frames pkt-lines and pipes bytes), mounted at a top-level `/git/{owner}/{repo}` prefix (optional `.git` suffix accepted) only when the engine flag is on; the git.<domain> DNS move is Phase D. Two design points recorded: (1) **the PackSource seam from the roadmap is the only way packs are consumed** — `FetchPack(ctx, repoPrefix, pack, dir)`: manifest pack entries stay repo-RELATIVE (`packs/<sha>.pack`) so manifests are layout-portable, and the prefix composes bucket keys; today's impl is full download with size-matched reuse on disk (idempotence), tomorrow's range-streaming impl swaps in with the same signature. (2) **References are re-materialized from the manifest on EVERY hydration** (packed-refs + HEAD from default_branch) — a stale cache can never serve refs the referee has moved; packs are the only sizeable artifacts and idempotence skips them. Verified with REAL `git clone` against the handler through an httptest server (v0 forced and v2 default): a fixture repo (commits + annotated tag) is repacked, uploaded to the MemStore as a manifest with refs from for-each-ref, hydrated, cloned, and the clone's files/describe/HEAD-sha asserted against the manifest; hydration idempotence proven with a counting store wrapper (zero pack refetches, byte-identical packed-refs). Interim resolver `FindRepoForGit` resolves slugs unscoped with an explicit ambiguity guard (defense-in-depth: project slugs are globally unique today, proven by test); repos whose content still lives on Forgejo have no manifest and 404 naturally after the per-repo Phase-D migration; B6 replaces the resolver with token-scoped auth and no cutover happens before it.

- 2026-11-12 — PR B1 (serverless epic, Phase B): git engine storage model + provisioning shipped, flag-off and inert. The four irreversible decisions are now in code, each pinned by tests: (1) **Manifest format** — the bucket-side partner of `git_repo_state` is a JSON manifest (`version=1, tenant_id, default_branch, refs[{name,target,peeled}], packs[], push_history tail, updated_at, storage_bytes`) with a deterministic golden test; decode is lenient about unknown fields (std json) but fails CLOSED on versions newer than the reader. Refinement of the roadmap sketch, recorded so it is deliberate: pack entries carry `{object, bytes, etag, idx_object, idx_bytes, idx_etag}` — the idx sidecar gets the same first-class metadata as the pack (bytes + etag), since streaming and `Head`-cheap validation need it equally; the sketch's `pack_size` folds into `bytes`. Push history is capped at 16 tail entries (the manifest is read on every cold start; the audit log keeps full history) and tenant-stamped like everything meterable. (2) **Ref-CAS semantics** — one `git_repo_state` row per repo (migration 000025): monotonic `revision` + `refs` jsonb + `storage_bytes` + `tenant_id` (nullable ON DELETE SET NULL like audit_log/pipeline_queue: metering never depends on joins surviving tenant deletion). The CAS is a single `UPDATE ... WHERE repo_id=? AND revision=?` — 0 rows checks existence and returns a typed `ErrRefCASLost` (a 20-goroutine race test proves exactly one winner); Postgres is THE commit point, the bucket manifest is a materialized view written through conditional puts. (3) **tenant_id propagation** — stamped on the referee row at provisioning AND in the manifest; CI rows already carried it (A1). (4) **Bucket layout** — `repos/{tenant}/{project}/{repo}/manifest.json + packs/<sha>.pack|.idx + tmp/`, segments path-escaped so a hostile slug can never leave its prefix; packs stay whole individually-addressable objects with etag+size recorded for the later range-request PackSource. Implementation keeps the dependency set unchanged: the S3 client is the spike's proven SigV4 signer lifted into `internal/objectstore` (stdlib only), with `ErrNotFound`/`ErrPreconditionFailed` typed errors and a `MemStore` implementing the same contract so engine/platform tests run credential-free. Provisioning (own mode, `QUILL_GIT_ENGINE_MODE=own` + `QUILL_GIT_S3_*` envs, validated complete at startup): manifest written create-if-absent FIRST, then repo row + referee row in ONE transaction (raw InTxTx), DB failure compensates by deleting the still-empty manifest — bucket and Postgres never disagree about existence; `CloneFrom` imports under own mode fail explicitly until the PR-D migration tool. Rollback = the flag stays off (Forgejo path untouched). Verified: conditional-write contract green against the live Scaleway bucket (gated roundtrip test — a helper bug where `do()` deferred body.Close before the caller read it was caught live, which mem tests alone would have missed); own-mode CreateRepo integration tests green; full `./check` green on a clean schema.

- 2026-11-12 — Chained/template workflows verified through the ciworker (post-A2/A3 investigation); three distinct behaviors, measured live with a local git repo + composite action template. (1) **Same-repo templates work** when the workflow starts with `actions/checkout`: Quill checks out the repo on the host, act runs with `BindWorkdir: false`, and act's local-checkout special case (`isLocalCheckout` → `CopyDir` of the host workdir into the job container's named volume) materializes the workspace — `uses: ./.github/actions/greet` then executed and its output landed in the step logs (run green). - 2026-11-11 — PR A2/A3 shaped by an implementation fact: **act v0.2.89 has no host execution mode.** Every workflow step runs through the Docker daemon (`runner.Config.Platforms` images; there is no "run the step in-process" path), so the planned Serverless-Job worker cannot work: gVisor sandboxes cannot host a Docker daemon (no DinD), and act's isolation model assumes it. Decision, confirmed with the owner: **the CI worker is an ephemeral Scaleway instance**, not a Serverless Job — the broker (a min_scale-0 Serverless Container, as planned in A2) ensures exactly one tagged DEV1-S instance (list-before-create), cloud-init installs Docker on first boot and runs the ciworker container (registry image, pinned tag); the worker drains the Quill queue (claim → heartbeat → act on the instance's own Docker → report), and self-terminates the instance on idle (poweroff → poll stopped → delete, via a pluggable Terminator interface). CI cost becomes instance-minutes only while jobs run; the idle floor is unchanged (RDB only). Rejected alternatives: reimplementing act's step engine in-process (a fork of act in all but name — forbidden by the epic constraints), DinD-in-gVisor (impossible), keeping act on the long-lived VM (the box being deprecated; the 2026-11-11 wedge is exactly this failure mode), and ephemeral gitea-act-runner registration (binds us to the Forgejo actions protocol the epic deletes). Same-binary runtime portability is retained: ciworker is a plain Go binary whose Scaleway-specific code (instance termination) sits behind a Terminator hook driven by env (SCW_INSTANCE_ID) — the same image runs later in Kapsule warm pools with termination disabled. Broker safety net: instances older than a 3h TTL are killed by the broker's ensure loop (a wedged worker whose ciworker died cannot self-terminate; without the TTL it would bill forever). Missed-wake backstop: a cron sweeper Job hitting the broker's `/wake` every few minutes — not yet in terraform (follow-up with the deploy wiring).

- 2026-11-11 — PR-0 GO/NO-GO spike executed: GO. - 2026-11-11 — Full-serverless roadmap adopted (plan only, no implementation yet): the platform migrates to all-compute-scale-to-zero on Scaleway — own git engine in the Quill backend (Object Storage bucket + Postgres ref-CAS, no Forgejo), CI as ephemeral Serverless Jobs, Zitadel as a Serverless Container with a separate setup Job, and the DEV1-S VM fully deprecated; idle floor = RDB Postgres only. Full roadmap: `deploy/scaleway/serverless-roadmap.md`. The irreversible-by-design items (decided now, before any code): (1) Postgres is the correctness referee for ref updates from day one — the SDB/S3 `If-Match` path is an optional fast path, never the source of truth; (2) bucket layout keeps packs as whole, individually addressable standard packfiles with a versioned manifest, so later streaming/partial hydration (range requests) is possible without re-layout; (3) `tenant_id` is stamped on every repo/push/CI row and in the manifest, with tenant-scoped metering (storage bytes, pushes, CI minutes) designed into the schema now; (4) the git-engine and CI-runner images must run unmodified on Serverless Containers and later warm pools (Kapsule), with a `tenants.runtime_hint ('serverless'|'warm')` column added unused; maintenance work (pack GC/repack/orphan cleanup) runs only as idempotent Serverless Jobs, never inline in request paths. Why: Scaleway's platform features may change under us (the fast-path bet), repo data outlives every other choice (bucket layout + manifest), and tenant metering/isolation retrofit costs multiply after real data exists. Alternatives rejected: S3-If-Match as the referee (correctness on a platform feature), archive-style blob layouts (block streaming forever), retrofitted tenancy (re-walk of every object after data lands). Frontend stays a min_scale-0 Serverless Container (static export impossible: Auth.js + server components + the /api/backend rewrite need a Node runtime per request).
